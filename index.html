10
แล้วต่างกันยังไง?
🧠 UX Design
  • โฟกัสที่ "ประสบการณ์" — รู้สึก, ใช้ง่าย
  • ดูแล Flow ตั้งแต่ก่อน–ระหว่าง–หลังใช้
  • เน้น โครงสร้าง (Structure / IA)
🎨 UI Design
  • โฟกัสที่ "หน้าตา" — สวย, จัดวาง
  • องค์ประกอบที่โต้ตอบได้ (ปุ่ม/ไอคอน)
  • เน้น การนำเสนอ (Visual)
🛣️ UX = ทางที่คนเดินจริง · UI = ทางที่เราปูสวยๆ — ดีที่สุดคือตรงกัน

Prioritization
22
จัดลำดับฟีเจอร์ด้วย MoSCoW
ของมีจำกัด เวลามีจำกัด — MoSCoW ช่วยให้ทั้งทีมเห็นตรงกันว่า "อะไรทำก่อน อะไรทำทีหลัง" แทนที่จะเถียงกันว่าฟีเจอร์ไหนสำคัญกว่า
📌
ตั้งต้นจาก Persona เสมอ: "Must / Should" วัดจาก Pain Points & Goals ของ user ที่เพิ่งทำ — ไม่ใช่ฟีเจอร์ที่เราชอบเอง
✅
Must Have — ต้องมี
หัวใจของระบบ ขาดไม่ได้เด็ดขาด ถ้าไม่มีคือ launch ไม่ได้ เช่น Login, ตะกร้า/สั่งซื้อ, ชำระเงิน
🔎 ลองถาม: "ถ้าตัดออก โปรเจกต์ยังใช้งานได้ไหม?" — ถ้าไม่ได้ = Must
⭐
Should Have — ควรมี
สำคัญมากแต่ยังไม่ถึงตาย เลื่อนไปเฟสหน้าได้โดยระบบไม่พัง เช่น ค้นหา, ตัวกรอง, แจ้งเตือน
ทำให้ประสบการณ์ดีขึ้นชัดเจน แต่ไม่ใช่สิ่งที่ทำให้ระบบ "มีชีวิต"
✨
Could Have — มีก็ดี
ของแถมที่เพิ่มความว้าว ไม่มีก็ไม่เป็นไร ทำเมื่อมีเวลา/งบเหลือ เช่น Dark Mode, ธีมสี, อนิเมชัน
เป็นกลุ่มแรกที่ "ตัดทิ้ง" ได้ถ้าเริ่มทำไม่ทัน
🚫
Won't Have — ยังไม่ทำ
ตกลงร่วมกันว่า "รอบนี้ยังไม่ทำ" ไม่ใช่ไม่ดี แต่ขอเก็บไว้ก่อน เช่น หลายภาษา, ระบบ AI แนะนำ
เขียนให้ชัดเพื่อกันทีมหลุดโฟกัส (scope creep)
💡 วิธีใช้จริง: ทำ Must ให้เสร็จก่อนเสมอ → ตั้งเวลา (time-box) แล้วค่อยไล่ Should → Could • ถ้าเวลาไม่พอ ตัดจากล่างขึ้นบน (Won't → Could → Should) อย่าแตะ Must

Component vs Design System
38
Component ≠ Design System
Component เป็นส่วนหนึ่งของ Design System — แต่ทำ Component อย่างเดียว ยังไม่ถือว่ามี Design System ที่สมบูรณ์
หัวข้อ 🧩 Componentชิ้นส่วน UI ที่นำกลับมาใช้ซ้ำได้ เช่น Button, Input, Card, Modal 📘 Design Systemมาตรฐานทั้งสี ตัวอักษร ระยะห่าง Component และกฎการใช้งานให้สอดคล้องกัน
🎯 เป้าหมายนำ UI กลับมาใช้ซ้ำสร้างมาตรฐานทั้ง Product
📐 ขอบเขตUI แต่ละชิ้นระบบการออกแบบทั้งหมด
🧪 ตัวอย่างButton, Input, ModalColors, Typography, Tokens, Components, Guidelines
⚙️ การใช้งานลดงานออกแบบและพัฒนาซ้ำทำให้ทีมออกแบบและพัฒนาไปในทิศทางเดียวกัน
👥 ผู้ใช้งานUX/UI, DeveloperUX/UI, Developer, Product Team

  • StatesDefault · Hover · Focus · Disabled · Loading

ระบุสีเอง ให้ชัด — AI ไม่ต้องเดา และทุกหน้าจะออกมาเป็นระบบเดียวกัน

Primary #5B5EE8Secondary #B9A8F5Accent #E8709ABackground #FFF8FCText #23213FSuccess #3E9E7EWarning #F2B45ADanger #C93A62
สร้าง "Design System" ของโปรเจกต์ [ชื่อระบบของกลุ่ม เช่น ระบบจองห้องประชุม] เป็นไฟล์ HTML เดียวจบ (รวม CSS + JS) ชื่อ design-system.html เปิดในเบราว์เซอร์ได้ทันที 🎨 สีของแบรนด์ (ใช้ตามนี้เท่านั้น ห้ามคิดสีเพิ่ม) - Primary: #5B5EE8 (Periwinkle) → ปุ่มหลัก ลิงก์ สิ่งที่อยากให้กด - Secondary: #B9A8F5 (Lavender) → ปุ่มรอง ไฮไลต์ - Accent: #E8709A (Rose Pink) → จุดเด่นเล็ก ๆ เช่น page indicator - Gradient: #6C6FF5 → #F3C6E3 → พื้นหลัง/ส่วนตกแต่งเท่านั้น (โทนพาสเทล ฝันๆ) - Background: #FFF8FC · Surface: #FFFFFF · Border: #F1E2EE - Text: #23213F · Text muted: #66627F - Success: #3E9E7E · Warning: #F2B45A · Danger: #C93A62 🔤 Typography: ฟอนต์ "IBM Plex Sans Thai" (Google Fonts) H1 32 · H2 24 · H3 20 · Body 16 · Small 14 📏 Spacing: 4 / 8 / 12 / 16 / 24 / 32 · Radius: 8 / 12 / 18 · Shadow 2 ระดับ 🧱 สิ่งที่ต้องมีในหน้า 1) Tokens — ประกาศทุกค่าเป็น CSS variables ใน :root (--color-primary, --space-4, --radius-md ...) แสดง swatch + ชื่อตัวแปร + hex กดคัดลอกได้ 2) Typography — ตัวอย่างทุกระดับ 3) Components — Button (Primary / Secondary / Ghost / Destructive × S/M/L + Hover / Focus / Disabled / Loading), Input + error, Select, Checkbox, Badge สถานะ, Card, Modal (กดเปิดได้จริง), Table 4) Usage Guidelines — ใต้แต่ละ component เขียน "ใช้เมื่อไหร่ / ไม่ควรใช้เมื่อไหร่" 5) ปุ่ม "คัดลอก tokens.css" ไว้ส่งให้เพื่อนในทีม ✅ กติกา - ทุก component ใช้ค่าจาก CSS variables เท่านั้น ห้าม hardcode สี - contrast ผ่าน WCAG AA และมี focus ring ชัดเจน - responsive ดูบนมือถือได้
